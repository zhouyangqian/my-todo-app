# Feature Specification: 进销存模块

**Feature Branch**: `005-erp-inventory`
**Created**: 2026-01-10
**Status**: Draft
**Input**: User description: "进销存模块：功能1: 实现采购功能 功能2： 实现销售功能 功能3： 实现仓库功能"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 采购管理 (Priority: P1)

系统能够完整地管理企业采购流程，包括供应商管理、采购订单创建、采购入库和采购退货。采购人员能够创建采购申请，经过审批后生成采购订单发送给供应商，货物到货后进行验收入库，并支持采购退货处理。

**Why this priority**: 采购管理是企业进销存的核心环节，没有采购就没有库存和销售。这是P1优先级的基础功能，必须首先实现才能支撑完整的业务流程。采购管理直接影响企业成本控制和供应链稳定性。

**Independent Test**: 可以通过完整的采购流程独立测试：创建供应商 → 创建采购订单 → 采购入库 → 查看库存增加。该流程验证了采购管理的核心价值，可以独立交付使用。

**Acceptance Scenarios**:

1. **Given** 系统中已维护供应商信息，**When** 采购人员创建采购订单（指定供应商、商品、数量、单价、交货日期），**Then** 系统生成采购订单记录，订单状态为"待审核"，并通知审批人

2. **Given** 采购订单待审核，**When** 审批人审核通过，**Then** 订单状态变更为"已确认"，系统自动发送订单通知给供应商

3. **Given** 采购订单已确认，**When** 采购人员创建采购入库单（关联采购订单，输入实收数量），**Then** 系统更新库存数量，记录库存流水，采购订单状态变更为"已完成"

4. **Given** 采购已入库的商品存在质量问题，**When** 采购人员创建采购退货单（指定退货商品、数量、原因），**Then** 系统扣减库存，记录退货流水，更新供应商退货统计

5. **Given** 需要新增供应商，**When** 采购人员创建供应商档案（名称、联系人、电话、地址、信用额度），**Then** 系统保存供应商信息，生成唯一供应商编号

6. **Given** 多个采购订单待处理，**When** 采购人员按供应商、日期、状态筛选订单，**Then** 系统显示符合条件的订单列表，支持导出Excel

7. **Given** 供应商信用额度已用完，**When** 采购人员尝试创建新采购订单，**Then** 系统提示"供应商信用额度不足"，阻止订单创建

### User Story 2 - 销售管理 (Priority: P1)

系统能够完整地管理企业销售流程，包括客户管理、销售报价、销售订单创建、销售出库和销售退货。销售人员能够创建销售报价单，客户确认后转为销售订单，仓库根据订单发货出库，并支持销售退货处理。

**Why this priority**: 销售管理是企业营收的核心环节，与采购管理共同构成进销存的主干业务。销售管理直接影响企业收入和客户关系管理，是P1优先级的关键功能。完整的销售流程管理能够提升客户满意度和订单处理效率。

**Independent Test**: 可以通过完整的销售流程独立测试：创建客户 → 创建销售订单 → 销售出库 → 查看库存减少 → 生成销售报表。该流程验证了销售管理的核心价值，可以独立交付使用。

**Acceptance Scenarios**:

1. **Given** 系统中已维护客户信息且有库存，**When** 销售人员创建销售订单（指定客户、商品、数量、单价、交货日期），**Then** 系统生成销售订单记录，订单状态为"待审核"，并检查库存是否充足

2. **Given** 销售订单待审核，**When** 审批人审核通过，**Then** 订单状态变更为"已确认"，系统锁定订单商品的库存数量

3. **Given** 销售订单已确认，**When** 仓库人员创建销售出库单（关联销售订单，扫描商品条码），**Then** 系统扣减锁定库存，记录库存流水，销售订单状态变更为"已完成"

4. **Given** 订单商品库存不足，**When** 销售人员创建销售订单，**Then** 系统提示"库存不足，当前可用库存XX件"，允许保存但标记为"缺货"状态

5. **Given** 客户需要退回已售商品，**When** 销售人员创建销售退货单（指定退货商品、数量、原因），**Then** 系统增加库存，记录退货流水，更新客户退货统计

6. **Given** 需要新增客户，**When** 销售人员创建客户档案（名称、联系人、电话、地址、信用额度），**Then** 系统保存客户信息，生成唯一客户编号

7. **Given** 客户欠款超过信用额度，**When** 销售人员尝试创建新销售订单，**Then** 系统提示"客户信用额度不足，当前欠款XX元"，可选择性阻止订单创建

8. **Given** 需要查看销售业绩，**When** 销售经理查询销售报表（按日期、商品、客户统计），**Then** 系统显示销售数量、销售额、毛利、回款情况等统计数据

### User Story 3 - 仓库管理 (Priority: P1)

系统能够全面管理仓库库存，包括库存查询、库存调拨、库存盘点和库存预警。仓库人员能够实时查看库存数量和库存流水，进行仓库间的库存调拨，定期盘点库存并处理盘点差异，系统自动监控库存并发出库存预警。

**Why this priority**: 仓库管理是进销存的基础设施，采购和销售都依赖于准确的库存数据。库存不准会导致采购决策失误、销售订单无法交付，直接影响企业运营。这是P1优先级的核心功能。

**Independent Test**: 可以通过库存管理流程独立测试：商品入库 → 查询库存 → 库存调拨 → 库存盘点 → 库存预警。该流程验证了库存管理的核心价值，可以独立交付使用。

**Acceptance Scenarios**:

1. **Given** 商品已入库，**When** 仓库人员查询库存（按商品、仓库、批次查询），**Then** 系统显示当前库存数量、可用数量、锁定数量、在途数量

2. **Given** A仓库商品库存过剩，B仓库库存不足，**When** 仓库人员创建库存调拨单（从A仓库调拨到B仓库，指定商品、数量），**Then** 系统扣减A仓库库存，增加B仓库库存，记录调拨流水

3. **Given** 需要进行库存盘点，**When** 仓库人员创建盘点单（指定仓库、盘点范围），系统生成盘点任务，**Then** 仓库人员录入实盘数量，系统自动计算盘点差异（盘盈/盘亏）

4. **Given** 盘点发现盘盈，**When** 仓库人员确认盘点结果，**Then** 系统增加库存，记录盘盈流水，生成盘盈报告

5. **Given** 盘点发现盘亏，**When** 仓库人员确认盘点结果（并填写盘亏原因），**Then** 系统扣减库存，记录盘亏流水，生成盘亏报告

6. **Given** 商品库存低于最低库存预警值，**When** 系统执行库存检查，**Then** 自动触发库存预警，通知采购人员和仓库主管

7. **Given** 商品库存高于最高库存预警值，**When** 系统执行库存检查，**Then** 自动触发积压预警，通知销售人员和仓库主管

8. **Given** 需要查看库存流水，**When** 仓库人员查询库存流水（按商品、日期、流水类型查询），**Then** 系统显示所有库存变动记录（入库、出库、调拨、盘点等）

9. **Given** 商品需要批次管理，**When** 商品入库，**Then** 系统记录批次号、生产日期、有效期，出库时按先进先出（FIFO）原则推荐批次

10. **Given** 商品即将过期（距离有效期不足XX天），**When** 系统执行批次检查，**Then** 自动触发效期预警，通知相关人员

### User Story 4 - 采购结算管理 (Priority: P2)

系统能够管理采购应付款项，记录采购订单的付款状态，支持付款申请和付款核销。财务人员能够查看供应商欠款，创建付款申请，审批后进行付款，并支持采购发票管理。

**Why this priority**: 采购结算是采购流程的财务闭环，影响企业与供应商的资金往来和信誉管理。虽然重要，但可以在核心采购流程稳定后再实施，因此是P2优先级。

**Independent Test**: 可以通过采购结算流程独立测试：创建采购订单 → 采购入库 → 生成应付记录 → 创建付款申请 → 付款核销。该流程验证了采购结算的核心价值。

**Acceptance Scenarios**:

1. **Given** 采购入库已完成，**When** 系统自动生成应付记录（金额=入库数量×单价），**Then** 应付记录关联采购订单和入库单，状态为"待付款"

2. **Given** 应付记录待付款，**When** 财务人员创建付款申请（指定应付记录、付款金额、付款方式），**Then** 系统生成付款申请单，状态为"待审批"

3. **Given** 付款申请审批通过，**When** 财务人员确认付款（录入付款凭证号），**Then** 系统更新应付记录为"已付款"，扣减供应商欠款

4. **Given** 供应商发票已到，**When** 财务人员关联发票到采购订单，**Then** 系统记录发票信息（发票号、发票日期、发票金额），支持后续对账

5. **Given** 需要查看供应商对账单，**When** 财务人员查询供应商往来账（按时间段查询），**Then** 系统显示采购订单、入库单、应付记录、付款记录的完整对账信息

---

### User Story 5 - 销售结算管理 (Priority: P2)

系统能够管理销售应收款项，记录销售订单的收款状态，支持收款登记和发票开具。财务人员能够查看客户欠款，登记收款，核销应收账款，并支持销售发票管理和对账单生成。

**Why this priority**: 销售结算是销售流程的财务闭环，直接影响企业回款和现金流管理。虽然重要，但可以在核心销售流程稳定后再实施，因此是P2优先级。

**Independent Test**: 可以通过销售结算流程独立测试：创建销售订单 → 销售出库 → 生成应收记录 → 登记收款 → 收款核销。该流程验证了销售结算的核心价值。

**Acceptance Scenarios**:

1. **Given** 销售出库已完成，**When** 系统自动生成应收记录（金额=出库数量×单价），**Then** 应收记录关联销售订单和出库单，状态为"待收款"

2. **Given** 客户付款到账，**When** 财务人员登记收款（指定应收记录、收款金额、收款方式、收款日期），**Then** 系统生成收款记录，更新应收记录状态，扣减客户欠款

3. **Given** 客户部分付款，**When** 财务人员登记收款（金额小于应收金额），**Then** 系统记录收款，扣减部分应收，应收记录状态为"部分收款"

4. **Given** 需要开具销售发票，**When** 财务人员创建销售发票（关联销售订单，录入发票信息），**Then** 系统保存发票记录，关联应收记录，支持发票打印

5. **Given** 需要查看客户对账单，**When** 财务人员查询客户往来账（按时间段查询），**Then** 系统显示销售订单、出库单、应收记录、收款记录、发票记录的完整对账信息

---

### User Story 6 - 报表与统计分析 (Priority: P2)

系统能够生成各类进销存报表，包括采购报表、销售报表、库存报表、利润分析报表。管理者能够通过多维度数据分析，了解企业经营状况，为采购决策、销售策略、库存管理提供数据支持。

**Why this priority**: 报表与统计分析是管理决策的重要工具，但需要在核心业务流程稳定、数据积累后再实施。因此是P2优先级的功能。

**Independent Test**: 可以通过报表查询和数据分析独立测试：执行采购/销售/库存操作 → 生成各类报表 → 验证数据准确性。该功能可以在业务数据基础上独立测试。

**Acceptance Scenarios**:

1. **Given** 系统中有采购数据，**When** 管理者查询采购报表（按时间段、供应商、商品统计），**Then** 系统显示采购数量、采购金额、供应商采购排名、商品采购排名等统计数据

2. **Given** 系统中有销售数据，**When** 管理者查询销售报表（按时间段、客户、商品统计），**Then** 系统显示销售数量、销售额、客户销售排名、商品销售排名等统计数据

3. **Given** 系统中有库存数据，**When** 管理者查询库存报表（按仓库、商品类别统计），**Then** 系统显示当前库存、库存金额、库存周转率、库存周转天数等统计数据

4. **Given** 系统中有采购和销售数据，**When** 管理者查询利润分析报表（按时间段统计），**Then** 系统显示销售收入、采购成本、毛利、毛利率等统计数据

5. **Given** 需要导出报表，**When** 管理者点击"导出Excel"按钮，**Then** 系统生成Excel文件并下载，包含完整的报表数据

6. **Given** 需要定制报表，**When** 管理者设置报表参数（统计维度、时间范围、筛选条件），**Then** 系统根据参数生成定制化报表

---

### User Story 7 - 商品与价格管理 (Priority: P2)

系统能够管理商品主数据，包括商品分类、商品档案、价格体系。采购人员能够维护商品信息，销售人员能够查询商品价格，系统支持多级价格体系（采购价、批发价、零售价）和价格促销管理。

**Why this priority**: 商品与价格管理是进销存的基础数据，可以先使用简化的商品信息实现核心流程，后续再完善价格体系。因此是P2优先级。

**Independent Test**: 可以通过商品和价格管理独立测试：创建商品分类 → 创建商品档案 → 设置价格体系 → 查询价格。该功能可以独立测试和交付。

**Acceptance Scenarios**:

1. **Given** 需要新增商品，**When** 采购人员创建商品档案（商品编码、名称、规格、单位、类别、参考价），**Then** 系统保存商品信息，生成唯一商品编码

2. **Given** 需要对商品分类，**When** 采购人员创建商品分类（分类名称、上级分类），**Then** 系统保存分类信息，支持多级分类树

3. **Given** 需要设置商品价格，**When** 采购人员设置商品价格（采购价、批发价、零售价，生效日期），**Then** 系统保存价格记录，支持价格历史查询

4. **Given** 商品需要进行促销，**When** 销售人员创建促销价格（指定商品、促销价、开始时间、结束时间），**Then** 系统保存促销价格，在促销期间自动应用促销价

5. **Given** 创建销售订单时，**When** 销售人员选择商品，**Then** 系统自动显示当前有效价格（根据客户类型显示批发价或零售价，如有促销则显示促销价）

---

### User Story 8 - 系统配置与权限管理 (Priority: P3)

系统能够进行系统参数配置，包括库存预警阈值、审批流程配置、单据编号规则。系统能够管理用户权限，不同角色（采购员、销售员、仓库员、财务、管理员）拥有不同的功能权限和数据权限。

**Why this priority**: 系统配置与权限管理是重要的系统管理功能，但可以在核心业务流程实现后再完善。初期可以使用固定的配置和简单的权限控制，因此是P3优先级。

**Independent Test**: 可以通过系统配置和权限管理独立测试：配置系统参数 → 设置用户角色 → 验证权限控制。该功能可以独立测试。

**Acceptance Scenarios**:

1. **Given** 需要设置库存预警，**When** 管理员配置商品库存阈值（最低库存、最高库存），**Then** 系统保存配置，当库存达到阈值时自动预警

2. **Given** 需要配置审批流程，**When** 管理员设置单据审批规则（如金额大于10000元需经理审批），**Then** 系统保存规则，单据创建时按规则自动路由审批人

3. **Given** 需要设置单据编号，**When** 管理员配置单据编号规则（前缀+日期+流水号），**Then** 系统按规则生成单据编号，保证唯一性

4. **Given** 不同角色用户登录，**When** 采购员登录，**Then** 只能看到采购相关功能，不能访问销售和财务功能

5. **Given** 多租户环境，**When** 租户A的用户登录，**Then** 只能看到租户A的数据，无法访问其他租户的数据

---

### Edge Cases

- 并发场景：多个用户同时操作同一商品的库存，如何保证库存数据一致性？
- 库存不足：销售订单商品库存不足时，是否允许创建订单？如何处理缺货订单？
- 退货处理：采购退货和销售退货时，如果原采购/销售价格已变更，按哪个价格结算？
- 盘点差异处理：盘点发现差异后，如何确认是盘盈还是盘亏？是否需要审批？
- 信用额度：供应商/客户信用额度超限后，是阻止订单创建还是仅提示警告？谁有权限 overriding？
- 价格变更：商品价格变更后，已创建但未完成的订单是否按新价格结算？
- 批次管理：商品批次混合存放时，如何指定出库批次？如何处理批次拆分？
- 单据撤销：已审核的单据是否允许撤销？撤销后如何处理库存和往来账？
- 数据权限：销售人员只能看到自己创建的订单，还是能看到所有人的订单？
- 跨仓库调拨：调拨单创建后，如何保证发货仓库及时发货？收货仓库如何确认收货？
- 期末处理：月末/年末如何处理未完成的采购和销售订单？是否需要结转？
- 发票红冲：已开票的销售发生退货，如何处理发票？是否支持红字发票？
- 历史数据：商品档案变更后，历史采购和销售记录是否显示变更后的信息还是保持原始信息？

- **FR-011**: 系统必须检查供应商信用额度，新建采购订单时如果供应商欠款超过信用额度，必须提示警告
- **FR-012**: 系统必须支持采购订单的查询功能，可以按供应商、日期、状态筛选，支持导出Excel

#### 销售管理功能

- **FR-013**: 系统必须允许用户创建客户档案，包括客户名称、编码、联系人、电话、地址、信用额度等基本信息
- **FR-014**: 系统必须支持客户档案的查询、修改、删除操作，删除前需检查是否有关联的销售订单
- **FR-015**: 系统必须允许用户创建销售订单，包括选择客户、添加商品明细（商品、数量、单价、交货日期）、填写备注
- **FR-016**: 系统必须在创建销售订单时检查商品库存是否充足，如果库存不足必须提示当前可用库存数量
- **FR-017**: 系统必须支持销售订单的审批流程，订单创建后进入"待审核"状态，审批人可以审核通过或驳回
- **FR-018**: 系统必须在销售订单审核通过后自动锁定订单商品的库存数量（锁定库存=订单数量）
- **FR-019**: 系统必须允许用户创建销售出库单，关联销售订单，扫描或输入商品，支持部分出库
- **FR-020**: 系统必须在销售出库时自动扣减锁定库存，记录库存流水（流水类型：销售出库）
- **FR-021**: 系统必须在销售出库后更新销售订单状态，部分出库时状态为"部分出库"，全部出库时状态为"已完成"
- **FR-022**: 系统必须允许用户创建销售退货单，关联销售订单或出库单，指定退货商品、数量、退货原因
- **FR-023**: 系统必须在销售退货时自动增加库存数量，记录库存流水（流水类型：销售退货）
- **FR-024**: 系统必须检查客户信用额度，新建销售订单时如果客户欠款超过信用额度，必须提示警告
- **FR-025**: 系统必须支持销售订单的查询功能，可以按客户、日期、状态筛选，支持导出Excel
- **FR-026**: 系统必须支持销售报价单功能，报价单可以转为销售订单

#### 仓库管理功能

- **FR-027**: 系统必须支持多仓库管理，商品库存可以按仓库分别统计
- **FR-028**: 系统必须提供库存查询功能，可以按商品、仓库、批次查询，显示当前库存、可用库存、锁定库存、在途库存
- **FR-029**: 系统必须允许用户创建库存调拨单，指定调出仓库、调入仓库、商品、调拨数量
- **FR-030**: 系统必须在库存调拨时扣减调出仓库库存、增加调入仓库库存，记录调拨流水
- **FR-031**: 系统必须支持库存盘点功能，允许用户创建盘点单，指定仓库、盘点范围
- **FR-032**: 系统必须支持盘点任务执行，用户录入实盘数量，系统自动计算盘点差异（差异=实盘数量-账面数量）
- **FR-033**: 系统必须在盘点确认后根据差异调整库存，盘盈时增加库存并记录盘盈流水，盘亏时扣减库存并记录盘亏流水
- **FR-034**: 系统必须支持库存预警功能，当商品库存低于最低库存或高于最高库存时，自动触发预警通知
- **FR-035**: 系统必须提供库存流水查询功能，显示所有库存变动记录，包括流水类型、数量、时间、操作人
- **FR-036**: 系统必须支持批次管理，商品入库时记录批次号、生产日期、有效期
- **FR-037**: 系统必须在商品出库时按先进先出（FIFO）原则推荐批次，允许用户手动选择批次
- **FR-038**: 系统必须支持效期预警，当商品批次即将过期时（距离有效期不足预警天数），自动触发预警通知

- **FR-039**: 系统必须在采购入库完成后自动生成应付记录，金额=入库数量×采购单价，状态为"待付款"
- **FR-040**: 系统必须支持应付记录查询，可以按供应商、订单、状态筛选
- **FR-041**: 系统必须允许用户创建付款申请，关联应付记录，指定付款金额、付款方式、期望付款日期
- **FR-042**: 系统必须支持付款申请审批流程，审批通过后才能执行付款
- **FR-043**: 系统必须允许用户确认付款，录入付款凭证号，更新应付记录状态为"已付款"，扣减供应商欠款
- **FR-044**: 系统必须支持采购发票管理，允许用户录入发票信息并关联到采购订单
- **FR-045**: 系统必须在销售出库完成后自动生成应收记录，金额=出库数量×销售单价，状态为"待收款"

- **FR-047**: 系统必须允许用户登记收款，关联应收记录，指定收款金额、收款方式、收款日期
- **FR-048**: 系统必须在登记收款后更新应收记录状态，扣减客户欠款，支持部分收款
- **FR-049**: 系统必须支持销售发票管理，允许用户创建销售发票并关联到销售订单

- **FR-054**: 系统必须支持供应商对账单，显示采购订单、入库单、应付记录、付款记录的完整对账信息
- **FR-055**: 系统必须支持客户对账单，显示销售订单、出库单、应收记录、收款记录的完整对账信息

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 用户能够在2分钟内完成一张采购订单的创建（假设订单明细为5行商品）
- **SC-002**: 用户能够在3分钟内完成一张销售订单的创建（假设订单明细为5行商品）
- **SC-003**: 仓库人员能够在30秒内完成一个商品的扫码出库操作
- **SC-004**: 库存查询响应时间在2秒以内，支持10万条库存记录
- **SC-005**: 采购入库后库存数据实时更新，延迟不超过1秒
- **SC-006**: 系统支持至少50个并发用户同时操作而不出现性能明显下降
- **SC-007**: 库存数据准确率达到99.9%，通过盘点验证账面库存与实物库存的一致性
- **SC-008**: 采购订单从创建到审核完成的平均处理时间不超过30分钟
- **SC-009**: 销售订单从创建到发货完成的平均处理时间不超过4小时
- **SC-010**: 报表生成时间在5秒以内，支持100万条业务数据的统计分析
- **SC-011**: 用户首次使用系统时，能够在没有培训的情况下完成基本的采购/销售/库存操作（通过界面引导和提示）
- **SC-012**: 系统支持至少10000个商品、1000个供应商、1000个客户的管理
- **SC-013**: 库存预警触发后，相关人员能够在5分钟内收到预警通知
- **SC-014**: 多租户环境下，不同租户的数据完全隔离，互不可见
- **SC-015**: 系统可用性达到99.5%，月度计划外停机时间不超过3.6小时

## Assumptions

1. **业务假设**:
   - 企业采用标准采购-销售-库存流程，没有复杂的跨公司调拨和转单需求
   - 商品采购和销售价格相对稳定，不需要频繁的价格调整
   - 供应商和客户的信用额度控制是必要的，但不是强制的，允许超越额度创建订单
   - 库存采用定期盘点制度，不是实时盘点
   - 批次管理仅针对需要批次的商品（如食品、药品），不是所有商品都需要批次管理
   - 发票管理是必要功能，但可以在业务完成后补录，不要求与业务单据同步

2. **技术假设**:
   - 使用Java 17+和Spring Boot 3.0作为后端技术栈
   - 使用Vue 3.0和Ant Design 6.1.4作为前端技术栈
   - 使用MySQL 8.0+存储业务数据
   - 使用Redis 7.0+缓存热点数据和会话数据
   - 使用MyBatis-Plus作为ORM框架
   - 系统部署在云服务器或本地服务器上，支持容器化部署

3. **数据假设**:
   - 商品编码采用唯一编码规则，不允许重复
   - 单据编号采用系统自动生成规则，保证唯一性和连续性
   - 库存流水保留所有历史记录，不删除，用于追溯和审计
   - 审计日志保留至少1年，用于合规和安全审计

4. **用户假设**:
   - 用户具备基本的计算机操作能力
   - 用户了解进销存业务流程
   - 用户使用PC端浏览器访问系统，屏幕分辨率不低于1920x1080
   - 用户数量在100人以内

5. **集成假设**:
   - 系统需要与用户认证模块集成（003-user-auth）
   - 系统需要与权限管理模块集成（002-permission-module）
   - 系统可能需要与财务系统对接，实现财务凭证自动生成（待定）
   - 系统可能需要与第三方物流系统对接，实现物流信息查询（待定）

6. **性能假设**:
   - 系统高峰期并发用户数为50人
   - 单表数据量在100万条以内
   - 报表统计基于月度数据，不是年度数据
   - 库存流水查询基于最近3个月数据，不是全量数据

7. **安全假设**:
   - 系统通过内网或VPN访问，不直接暴露到公网
   - 所有操作都需要用户认证和权限验证
   - 敏感操作（如删除、审批）需要操作确认
   - 数据传输采用HTTPS加密
