# Feature Specification: 用户模块

**Feature Branch**: `001-user-module`
**Created**: 2026-01-10
**Status**: Draft
**Input**: User description: "我要做一个用户模块：功能1:里面有SaaS租户下用户的管理 功能2：租户赋予用户权限"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 租户用户管理 (Priority: P1)

租户管理员能够管理自己租户下的用户账户，包括创建、查看、编辑、禁用和删除用户，确保租户数据隔离和安全性。

**Why this priority**: 这是多租户 SaaS 系统的核心基础功能。没有用户管理，租户无法使用系统，这是 P1 优先级的 MVP 功能。

**Independent Test**: 可以独立测试租户管理员在其租户内完成用户全生命周期管理，验证租户隔离性（不同租户管理员看不到彼此的用户）。

**Acceptance Scenarios**:

1. **Given** 租户管理员已登录，**When** 创建新用户并填写必填信息（用户名、邮箱、角色），**Then** 用户被成功创建并分配到当前租户，系统显示成功消息
2. **Given** 租户管理员已登录，**When** 查看用户列表，**Then** 只显示本租户的用户，不显示其他租户的用户
3. **Given** 租户管理员已登录，**When** 编辑用户信息（如修改角色或状态），**Then** 用户信息被更新，变更记录被审计日志
4. **Given** 租户管理员已登录，**When** 禁用一个用户，**Then** 该用户无法登录系统，但仍保留在用户列表中
5. **Given** 租户管理员已登录，**When** 删除一个用户，**Then** 用户被软删除（标记为已删除）且无法恢复
6. **Given** 租户管理员已登录，**When** 搜索用户（按用户名或邮箱），**Then** 只返回本租户内匹配的用户

---

### User Story 2 - 用户权限分配 (Priority: P2)

租户管理员能够为用户分配和调整权限，通过角色或直接权限授予的方式控制用户在系统中的访问范围。

**Why this priority**: 权限管理是安全合规的关键要求。在用户能够被管理（P1）之后，需要确保用户只能访问其被授权的功能，这是 P2 优先级。

**Independent Test**: 可以独立测试租户管理员为用户分配权限，验证权限生效（用户获得/失去相应功能的访问权限）。

**Acceptance Scenarios**:

1. **Given** 租户管理员已登录，**When** 为用户分配角色（如"管理员"、"普通用户"），**Then** 用户获得该角色对应的所有权限
2. **Given** 租户管理员已登录，**When** 直接为用户授予特定权限（不依赖角色），**Then** 用户获得该特定权限的访问能力
3. **Given** 租户管理员已登录，**When** 撤销用户的角色或权限，**Then** 用户立即失去相应功能的访问权限
4. **Given** 租户管理员已登录，**When** 查看用户的权限列表，**Then** 显示用户拥有的所有权限（来自角色和直接授予）
5. **Given** 用户已分配权限，**When** 用户尝试访问未授权的功能，**Then** 系统显示"权限不足"错误消息并记录审计日志
6. **Given** 租户管理员已登录，**When** 创建自定义角色并分配权限组合，**Then** 新角色可以被分配给租户内的其他用户

---

### User Story 3 - 批量用户操作 (Priority: P2)

租户管理员能够批量操作用户账户，包括批量禁用、批量删除、批量分配角色，提高管理效率。

**Why this priority**: 批量操作是用户管理的高频需求，特别是在企业场景下需要批量处理大量用户时，这是 P2 优先级的功能增强。

**Independent Test**: 可以独立测试租户管理员批量选择用户并执行操作，验证批量操作的正确性和审计日志记录。

**Acceptance Scenarios**:

1. **Given** 租户管理员已登录，**When** 批量选择 10 个用户并禁用，**Then** 所有选中的用户被禁用，系统显示操作结果（成功/失败数量）
2. **Given** 租户管理员已登录，**When** 批量选择用户并删除，**Then** 所有选中的用户被软删除，系统提示确认并在操作后记录审计日志
3. **Given** 租户管理员已登录，**When** 批量选择用户并分配角色，**Then** 所有选中的用户被分配指定角色，原有角色被替换或追加
4. **Given** 租户管理员已登录，**When** 批量操作中部分用户操作失败，**Then** 系统显示详细的失败原因（如"用户不存在"、"权限不足"），成功的操作不受影响
5. **Given** 租户管理员已登录，**When** 批量选择超过 100 个用户，**Then** 系统提示"批量操作最多支持 100 个用户"，并限制操作执行
6. **Given** 租户管理员已登录，**When** 执行批量操作，**Then** 操作记录到审计日志，包含操作类型、目标用户列表、操作人、操作时间

---

### User Story 4 - 用户导入/导出 (Priority: P2)

租户管理员能够通过 Excel 文件批量导入用户，或将用户列表导出为 Excel 文件，方便数据迁移和备份。

**Why this priority**: 用户导入/导出是企业初始化和数据维护的常见需求，特别是从其他系统迁移用户数据时，这是 P2 优先级的功能增强。

**Independent Test**: 可以独立测试租户管理员上传 Excel 文件导入用户，以及导出用户列表为 Excel 文件。

**Acceptance Scenarios**:

1. **Given** 租户管理员已登录，**When** 下载用户导入模板，**Then** 系统提供标准 Excel 模板（包含必填字段：用户名、邮箱、角色）
2. **Given** 租户管理员已登录，**When** 上传填写好的 Excel 文件（包含 50 个用户），**Then** 系统解析文件并创建用户，显示导入结果（成功/失败数量）
3. **Given** 租户管理员已登录，**When** 上传的 Excel 文件中存在重复的用户名或邮箱，**Then** 系统跳过重复记录并在结果中提示"用户名已存在"
4. **Given** 租户管理员已登录，**When** 上传的 Excel 文件格式不正确（缺少必填列），**Then** 系统提示"文件格式错误"，并显示具体的错误信息
5. **Given** 租户管理员已登录，**When** 导入用户数量超过租户上限，**Then** 系统提示"用户数量已达上限"，并停止导入
6. **Given** 租户管理员已登录，**When** 导出用户列表，**Then** 系统生成 Excel 文件并下载，文件包含所有用户的基本信息（用户名、邮箱、角色、状态、创建时间）
7. **Given** 租户管理员已登录，**When** 导出用户列表时添加筛选条件（如只导出启用的用户），**Then** 导出的 Excel 文件只包含符合筛选条件的用户
8. **Given** 租户管理员已登录，**When** 上传超过 1000 条记录的 Excel 文件，**Then** 系统提示"单次导入最多支持 1000 条记录"，并限制操作执行

---

### Edge Cases

- 当租户被删除时，该租户下的所有用户如何处理？
- 当用户同时属于多个租户时，如何切换租户上下文？
- 当租户管理员试图修改/删除比自己权限更高的用户时，系统如何响应？
- 当用户被禁用时，该用户的活跃会话如何处理？
- 当权限冲突时（如通过角色获得权限A，但被直接撤销权限A），以哪个为准？
- 当租户用户数量达到上限（5个用户）时，创建新用户如何处理？

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统必须支持租户管理员创建用户账户，用户必须关联到特定租户
- **FR-001-1**: 系统必须在创建用户前检查租户用户数量限制（默认5个，可升级），超限时拒绝创建
- **FR-002**: 系统必须确保租户数据隔离，用户只能看到和操作其所属租户的数据
- **FR-003**: 系统必须支持查看租户用户列表，提供分页和搜索功能
- **FR-004**: 系统必须支持编辑用户基本信息（用户名、邮箱、手机号、状态）
- **FR-005**: 系统必须支持禁用用户账户，被禁用用户无法登录
- **FR-006**: 系统必须支持删除用户账户，采用软删除方式保留数据
- **FR-007**: 系统必须支持为用户分配角色，角色对应一组预定义的权限
- **FR-008**: 系统必须支持直接为用户授予或撤销特定权限，不依赖角色
- **FR-009**: 系统必须在每次权限变更时记录审计日志（谁、何时、对谁、做了什么）
- **FR-010**: 系统必须支持创建自定义角色并配置权限组合
- **FR-011**: 系统必须在用户访问受保护资源时验证其权限，无权限时拒绝访问
- **FR-012**: 系统必须支持用户查看自己的权限列表（来自角色和直接授予）
- **FR-013**: 系统必须记录所有用户管理操作的审计日志（创建、编辑、删除、权限变更）
- **FR-014**: 系统必须支持按用户名或邮箱搜索用户（仅限本租户）

**批量操作**：
- **FR-015**: 系统必须支持批量禁用用户（最多 100 个）
- **FR-016**: 系统必须支持批量删除用户（软删除，最多 100 个）
- **FR-017**: 系统必须支持批量分配角色（支持替换或追加模式，最多 100 个）
- **FR-018**: 系统必须在批量操作失败时显示详细错误信息（成功/失败数量、失败原因）
- **FR-019**: 系统必须记录批量操作的审计日志（包含操作类型、目标用户列表、操作人、操作时间）

**用户导入/导出**：
- **FR-020**: 系统必须提供标准 Excel 导入模板下载（包含必填字段和说明）
- **FR-021**: 系统必须支持通过 Excel 文件批量导入用户（最多 1000 条记录）
- **FR-022**: 系统必须在导入时验证数据格式（必填字段、邮箱格式、重复用户名/邮箱）
- **FR-023**: 系统必须在导入时检查租户用户数量限制，超限时停止导入
- **FR-024**: 系统必须支持导出用户列表为 Excel 文件（包含用户基本信息）
- **FR-025**: 系统必须支持带筛选条件的导出（如只导出启用用户、特定角色用户）

### Key Entities

- **租户**: SaaS 系统中的组织单位，拥有独立的用户数据和权限配置。包含租户名称、租户状态、用户数量限制（默认5个，可升级）等属性。
- **用户 (User)**: 系统的使用者，属于唯一一个租户。包含用户名、邮箱、手机号、密码哈希、账户状态、所属租户等属性。一个用户在一个租户内只能有一个身份。
- **角色 (Role)**: 权限的集合，由租户管理员创建和管理。包含角色名称、描述、关联的权限列表。角色属于特定租户。
- **权限 (Permission)**: 系统中可执行的操作或可访问的资源。包含权限代码（如 "user:create"、"user:view"）、权限名称、描述。权限是系统级别的，角色和用户通过关联获得权限。
- **用户-角色关联 (UserRole)**: 用户和角色之间的多对多关系，记录用户在特定租户下被分配的角色。
- **用户-权限关联 (UserPermission)**: 用户和权限之间的直接关联，记录用户被直接授予的额外权限（不通过角色）。
- **审计日志 (AuditLog)**: 记录所有用户管理和权限变更操作。包含操作类型、操作人、目标用户、操作时间、操作详情、所属租户。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 租户管理员能够在 2 分钟内完成新用户创建并分配角色
- **SC-002**: 系统能够支持单个租户下至少 10,000 个用户账户而不影响性能（性能基准，默认租户上限为5个用户，可升级）
- **SC-003**: 权限变更在 1 秒内生效，用户立即获得或失去相应功能的访问权限
- **SC-004**: 用户列表查询响应时间在 500ms 以内（1000 用户规模）
- **SC-005**: 租户数据隔离率达到 100%，租户管理员无法查看或操作其他租户的用户数据
- **SC-006**: 100% 的用户管理和权限变更操作被记录在审计日志中
- **SC-007**: 用户能够通过搜索在 3 秒内找到目标用户（假设 1000 用户规模）
- **SC-008**: 批量操作 100 个用户在 10 秒内完成
- **SC-009**: 用户导入 1000 条记录在 30 秒内完成
- **SC-010**: 用户导出 10000 条记录在 15 秒内完成并生成 Excel 文件

## Assumptions

1. **模块边界**: 本模块专注于**已有租户内部的用户 CRUD 和权限管理**，不负责身份认证（注册/登录/密码重置），这些功能由 003-user-auth 模块提供。
2. **身份认证依赖**: 依赖 003-user-auth 模块提供的身份认证机制，本功能假设用户已经通过认证并携带有效的 JWT Token（包含用户 ID 和租户 ID）。
3. **权限模型**: 采用基于角色（RBAC）和直接权限授予的混合模型，既有角色的便捷性，也有直接权限的灵活性。权限定义由 002-permission-module 提供。
4. **租户上下文**: 假设系统已实现租户上下文识别（通过 JWT Token 中的租户ID或请求头），用户操作始终在租户上下文中执行。
5. **软删除**: 删除用户时采用软删除（标记为已删除）而非物理删除，以便数据恢复和审计。
6. **超级管理员**: 假设存在系统级别的超级管理员（如 SaaS 平台管理员），可以管理所有租户，但这不属于本功能范围。
7. **默认角色**: 每个租户创建时自动包含默认角色（如"租户管理员"、"普通用户"），新用户默认分配"普通用户"角色。
8. **Excel 处理**: 使用 Apache POI（Java）或类似库处理 Excel 文件，导入操作异步执行，导出操作同步执行（小数据量）或异步执行（大数据量）。
9. **批量操作限制**: 批量操作限制为 100 个用户，避免单次操作时间过长导致超时。
10. **导入默认密码**: 批量导入的用户默认密码设置为固定值（如"123456"），首次登录后强制修改密码（由 003-user-auth 模块处理）。
