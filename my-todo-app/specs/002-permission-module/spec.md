# Feature Specification: 权限模块

**Feature Branch**: `002-permission-module`
**Created**: 2026-01-10
**Status**: Draft
**Input**: User description: "我要做一个权限模块：功能1: 实现接口权限、数据权限、过滤器对权限的过滤、集成权限注解、以供其他项目使用 功能2：对权限角色组的管理 功能3：实现一个权限的功能的接口以供其他项目使用、不用再在配置文件里配置、也不要强实现 功能4：与前端构建一个长通话链接或者消息推送、如同账号多人登录挤掉前面的账号、下线过期token 功能5：黑账号功能、租户把子用户下线功能"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 接口与数据权限控制 (Priority: P1)

系统提供接口权限和数据权限的控制能力，通过过滤器、注解等方式实现权限验证，可被其他项目集成使用，确保接口安全和数据隔离。

**Why this priority**: 这是多租户 SaaS 系统安全的基础。没有接口和数据权限控制，任何用户都可以访问任何接口和数据，这是 P1 优先级的安全核心功能。

**Independent Test**: 可以独立测试通过注解和过滤器对接口进行权限拦截，验证有权限的用户可以访问，无权限的用户被拒绝。

**Acceptance Scenarios**:

1. **Given** 用户已登录并拥有特定权限，**When** 访问带有权限注解的接口，**Then** 请求成功通过，返回正常响应
2. **Given** 用户已登录但无相应权限，**When** 访问带有权限注解的接口，**Then** 请求被拦截，返回权限不足错误
3. **Given** 用户已登录并拥有数据权限，**When** 查询数据，**Then** 只返回该用户有权访问的数据（基于租户、部门等维度过滤）
4. **Given** 用户已登录但无数据权限，**When** 查询数据，**Then** 返回空结果或权限不足提示
5. **Given** 开发者集成权限模块，**When** 在接口方法上添加权限注解，**Then** 权限自动生效，无需额外配置

---

### User Story 2 - 角色组管理 (Priority: P2)

租户管理员能够创建和管理角色组，将权限组合成角色并分配给用户，简化权限管理流程。

**Why this priority**: 角色组是权限管理的核心机制，通过角色可以批量授予权限，这是 P2 优先级的功能。

**Independent Test**: 可以独立测试租户管理员创建角色、分配权限、将角色分配给用户，验证用户获得相应权限。

**Acceptance Scenarios**:

1. **Given** 租户管理员已登录，**When** 创建新角色并选择权限组合，**Then** 角色被成功创建
2. **Given** 租户管理员已登录，**When** 编辑角色的权限列表，**Then** 角色的权限被更新
3. **Given** 租户管理员已登录，**When** 删除角色，**Then** 角色被删除，拥有该角色的用户失去相应权限
4. **Given** 租户管理员已登录，**When** 为用户分配角色，**Then** 用户获得该角色的所有权限
5. **Given** 租户管理员已登录，**When** 撤销用户的角色，**Then** 用户立即失去该角色的权限

---

### User Story 3 - 动态权限配置接口 (Priority: P3)

提供权限管理的动态接口，支持通过接口进行权限的增删改查，无需修改配置文件或重启服务，实现权限的热更新。

**Why this priority**: 动态权限配置提升了系统的灵活性，减少配置文件维护成本，这是 P3 优先级的增强功能。

**Independent Test**: 可以独立测试通过接口动态添加、修改、删除权限，验证权限变更立即生效且无需重启服务。

**Acceptance Scenarios**:

1. **Given** 系统管理员调用权限接口，**When** 添加新的权限定义，**Then** 权限被成功添加并可立即使用
2. **Given** 系统管理员调用权限接口，**When** 修改权限的名称或描述，**Then** 权限信息被更新
3. **Given** 系统管理员调用权限接口，**When** 删除权限，**Then** 权限被删除，相关角色和用户的权限关联被清除
4. **Given** 权限通过接口添加后，**When** 开发者在代码中使用该权限注解，**Then** 注解生效，权限验证正常工作
5. **Given** 权限通过接口删除后，**When** 用户访问需要该权限的接口，**Then** 访问被拒绝

---

### User Story 4 - 实时会话管理 (Priority: P4)

系统通过长连接或消息推送与前端保持通信，实现账号挤号登录、强制下线、过期 Token 清理等功能，提升安全性和用户体验。

**Why this priority**: 实时会话管理是安全增强功能，可以防止账号共享和会话劫持，这是 P4 优先级的安全增强功能。

**Independent Test**: 可以独立测试同一账号在多个设备登录时的挤号行为，以及管理员强制下线用户的效果。

**Acceptance Scenarios**:

1. **Given** 用户在设备 A 上已登录，**When** 同一账号在设备 B 上登录，**Then** 设备 A 上的用户被强制下线并收到通知
2. **Given** 管理员强制下线某个用户，**When** 下线指令发送，**Then** 该用户在所有设备上的会话被终止，用户收到下线通知
3. **Given** 用户的 Token 已过期，**When** 用户尝试访问受保护的接口，**Then** 请求被拒绝，用户被重定向到登录页
4. **Given** 用户被强制下线，**When** 用户尝试继续操作，**Then** 系统显示"账号已在其他设备登录"或"已被管理员下线"的提示
5. **Given** 系统检测到异常登录行为（如频繁更换 IP），**When** 触发安全策略，**Then** 相关会话被终止并记录安全日志

---

### User Story 5 - 黑名单与强制下线 (Priority: P5)

系统管理员和租户管理员能够将用户加入黑名单并强制下线，也可以将黑名单用户恢复正常状态，实现多级别的用户访问控制。

**Why this priority**: 黑名单功能是管理用户的有效手段，用于快速处理违规或异常账户。系统管理员可跨租户管理黑名单，租户管理员可管理本租户黑名单，这是 P5 优先级的管理功能。

**Independent Test**: 可以独立测试系统管理员和租户管理员将用户加入/移出黑名单，验证用户状态变更立即生效。

**Acceptance Scenarios**:

1. **Given** 租户管理员已登录，**When** 将某个子用户加入黑名单，**Then** 该用户被立即强制下线
2. **Given** 用户在黑名单中，**When** 尝试登录系统，**Then** 登录被拒绝，提示"账号已被禁用"
3. **Given** 租户管理员已登录，**When** 将用户从黑名单移除，**Then** 用户可以重新登录系统
4. **Given** 系统管理员已登录，**When** 将任意租户的用户加入黑名单，**Then** 该用户被立即强制下线
5. **Given** 系统管理员已登录，**When** 将任意租户的黑名单用户移除，**Then** 用户可以重新登录系统
6. **Given** 租户管理员已登录，**When** 查看黑名单，**Then** 显示本租户所有被禁用的用户及其原因
7. **Given** 系统管理员已登录，**When** 查看黑名单，**Then** 显示所有租户被禁用的用户及其原因
8. **Given** 用户被强制下线（未加入黑名单），**When** 用户重新登录，**Then** 可以正常登录

---

### User Story 6 - 权限模板 (Priority: P3)

租户管理员能够使用预定义的权限模板快速创建角色，减少重复配置工作，提升角色创建效率。

**Why this priority**: 权限模板可以大幅减少角色配置时间，特别是在创建常用角色（如"销售"、"财务"、"管理员"）时，这是 P3 优先级的效率提升功能。

**Independent Test**: 可以独立测试租户管理员使用权限模板创建角色，验证角色自动获得模板中定义的权限。

**Acceptance Scenarios**:

1. **Given** 租户管理员已登录，**When** 查看权限模板列表，**Then** 显示系统预定义的模板（如"基础用户"、"部门经理"、"系统管理员"）和租户自定义模板
2. **Given** 租户管理员已登录，**When** 选择"销售经理"模板创建角色，**Then** 新角色自动获得该模板定义的所有权限（如"客户:view"、"订单:create"、"订单:approve"）
3. **Given** 租户管理员已登录，**When** 基于模板创建角色后调整权限（添加或移除），**Then** 角色权限被更新，模板本身不受影响
4. **Given** 租户管理员已登录，**When** 创建自定义权限模板，**Then** 模板被保存并可复用，其他租户管理员也能看到该模板
5. **Given** 租户管理员已登录，**When** 删除自定义权限模板，**Then** 模板被删除，已使用该模板创建的角色不受影响
6. **Given** 租户管理员已登录，**When** 编辑权限模板的权限列表，**Then** 模板被更新，但已存在的角色不受影响（仅影响后续创建的角色）

---

### User Story 7 - 扩展数据权限 (Priority: P3)

系统提供更丰富的数据权限控制维度，支持按部门、项目、个人等多种方式过滤数据，满足复杂业务场景的数据隔离需求。

**Why this priority**: 扩展数据权限是复杂业务场景的必要功能，特别是企业内部需要按部门、项目进行数据隔离时，这是 P3 优先级的功能增强。

**Independent Test**: 可以独立测试不同数据权限配置下用户查询数据的结果，验证数据过滤的正确性。

**Acceptance Scenarios**:

1. **Given** 用户拥有"全部数据"权限，**When** 查询订单列表，**Then** 返回租户内所有订单数据
2. **Given** 用户拥有"本部门数据"权限，**When** 查询订单列表，**Then** 只返回用户所属部门的订单数据
3. **Given** 用户拥有"本人数据"权限，**When** 查询订单列表，**Then** 只返回用户自己创建的订单数据
4. **Given** 用户拥有"指定项目数据"权限并关联项目 A 和 B，**When** 查询订单列表，**Then** 只返回项目 A 和 B 的订单数据
5. **Given** 用户拥有"本部门及下级部门"权限，**When** 查询订单列表，**Then** 返回本部门及所有下级部门的订单数据
6. **Given** 用户同时拥有多个数据权限规则（如"本人数据"+"特定项目"），**When** 查询订单列表，**Then** 返回满足任一规则的数据（OR 逻辑）
7. **Given** 开发者在接口上添加数据权限注解，**When** 注解指定权限类型为"部门"，**Then** 查询自动按部门过滤，无需手动编写过滤代码

---

### User Story 8 - 角色继承 (Priority: P4)

系统支持角色之间的继承关系，子角色自动继承父角色的所有权限，减少权限配置的重复工作，便于构建层级化的权限体系。

**Why this priority**: 角色继承可以简化大型企业的权限管理，特别是存在明显角色层级时（如"总经理"继承"部门经理"继承"员工"），这是 P4 优先级的高级功能。

**Independent Test**: 可以独立测试创建带继承关系的角色，验证子角色自动获得父角色的权限。

**Acceptance Scenarios**:

1. **Given** 租户管理员已登录，**When** 创建子角色并指定父角色，**Then** 子角色自动获得父角色的所有权限
2. **Given** 子角色继承了父角色权限，**When** 父角色的权限被更新（添加或移除），**Then** 子角色的权限同步更新
3. **Given** 子角色继承了父角色权限，**When** 为子角色单独添加额外权限，**Then** 子角色同时拥有继承权限和额外权限
4. **Given** 租户管理员已登录，**When** 删除父角色，**Then** 系统提示"该角色被其他角色继承，无法删除"，或提供级联删除选项
5. **Given** 角色存在多级继承（A→B→C），**When** A 角色的权限变更，**Then** B 和 C 角色的权限同步更新
6. **Given** 租户管理员已登录，**When** 查询角色的权限详情，**Then** 显示"继承权限"和"自有权限"两个部分，清晰展示权限来源
7. **Given** 子角色与父角色存在权限冲突（如子角色明确拒绝某权限），**When** 验证权限，**Then** 子角色的拒绝权限优先（子角色权限覆盖父角色）

---

### Edge Cases

- 当权限配置接口被恶意调用时，系统如何防止权限篡改？
- 当网络中断导致长连接断开时，前端如何处理会话状态？
- 当用户同时被踢出和 Token 过期同时发生时，优先显示哪个提示？
- 当黑名单用户数量达到上限时，系统如何处理？
- 当权限变更时，已登录的用户的权限如何更新？是否需要重新登录？
- 当租户被删除时，该租户的权限配置和黑名单如何处理？
- 当系统管理员和租户管理员同时操作同一用户的黑名单状态时，以哪个操作为准？
- 当用户在黑名单被移除后 5 秒内重新登录，但缓存未更新时，如何处理？
- 当黑名单历史记录过多时，是否需要归档或清理策略？
- 当权限模板被删除后，已使用该模板创建的角色如何处理？
- 当角色存在循环继承（A继承B，B继承A）时，系统如何检测和阻止？
- 当用户拥有多个数据权限规则时，如何处理规则冲突？
- 当父角色的权限被撤销时，子角色的继承权限如何处理？
- 当数据权限过滤字段不存在于查询表时，系统如何降级处理？

## Requirements *(mandatory)*

### Functional Requirements

**接口与数据权限控制**：
- **FR-001**: 系统必须支持通过注解方式声明接口所需的权限
- **FR-002**: 系统必须在请求处理前验证用户是否拥有所需权限
- **FR-003**: 系统必须支持数据权限过滤，基于租户、部门等维度限制数据访问范围
- **FR-004**: 系统必须提供权限过滤器，自动拦截无权限的请求
- **FR-005**: 系统必须记录所有权限验证失败的审计日志
- **FR-006**: 权限模块必须可被其他项目通过依赖方式集成使用

**角色组管理**：
- **FR-007**: 系统必须支持租户管理员创建、编辑、删除角色
- **FR-008**: 系统必须支持为角色分配多个权限
- **FR-009**: 系统必须支持为用户分配多个角色
- **FR-010**: 系统必须支持查询用户拥有的所有权限（来自角色和直接授予）
- **FR-011**: 系统必须支持角色的启用/禁用状态

**动态权限配置**：
- **FR-012**: 系统必须提供接口进行权限的增删改查操作
- **FR-013**: 权限变更必须立即生效，无需重启服务
- **FR-014**: 系统必须支持权限的层级结构（如模块:功能:操作）
- **FR-015**: 系统必须验证权限代码的唯一性

**实时会话管理**：
- **FR-016**: 系统必须支持同一账号只能有一个活跃会话（挤号登录）
- **FR-017**: 系统必须支持管理员强制下线指定用户
- **FR-018**: 系统必须通过长连接或消息推送向前端发送下线通知
- **FR-019**: 系统必须自动清理过期的 Token 和会话
- **FR-020**: 系统必须记录所有会话管理操作的审计日志

**黑名单与强制下线**：
- **FR-021**: 系统必须支持租户管理员将子用户加入黑名单
- **FR-022**: 系统必须支持系统管理员将任意租户的用户加入黑名单
- **FR-023**: 黑名单用户必须被立即强制下线
- **FR-024**: 黑名单用户必须无法登录系统
- **FR-025**: 系统必须支持租户管理员将用户从黑名单移除（取消黑户状态）
- **FR-026**: 系统必须支持系统管理员将任意租户的用户从黑名单移除（取消黑户状态）
- **FR-027**: 系统必须支持租户管理员查看本租户的黑名单
- **FR-028**: 系统必须支持系统管理员查看所有租户的黑名单
- **FR-029**: 系统必须支持黑名单原因记录和审计
- **FR-030**: 黑名单状态变更必须记录操作人和变更时间

**权限模板**：
- **FR-031**: 系统必须提供预定义的权限模板（如"基础用户"、"部门经理"、"系统管理员"）
- **FR-032**: 系统必须支持租户管理员创建自定义权限模板
- **FR-033**: 系统必须支持基于模板快速创建角色（自动获得模板权限）
- **FR-034**: 系统必须支持编辑和删除自定义权限模板
- **FR-035**: 基于模板创建的角色必须独立于模板存在，模板变更不影响已创建的角色

**扩展数据权限**：
- **FR-036**: 系统必须支持多种数据权限类型（全部数据、本部门数据、本人数据、指定项目数据、本部门及下级部门）
- **FR-037**: 系统必须支持用户同时拥有多个数据权限规则（OR 逻辑）
- **FR-038**: 系统必须支持通过注解声明数据权限类型（如 @DataPermission(type = DataPermissionType.DEPT)）
- **FR-039**: 数据权限过滤必须自动应用于 SQL 查询（通过 MyBatis-Plus 拦截器）
- **FR-040**: 系统必须在数据权限过滤字段不存在时降级处理（不影响查询执行）

**角色继承**：
- **FR-041**: 系统必须支持角色之间的继承关系（一个角色可以指定父角色）
- **FR-042**: 子角色必须自动继承父角色的所有权限
- **FR-043**: 父角色的权限变更必须同步到所有子角色
- **FR-044**: 系统必须支持多级角色继承（如 A→B→C）
- **FR-045**: 系统必须检测并阻止循环继承（如 A继承B，B继承A）
- **FR-046**: 系统必须阻止删除被其他角色继承的父角色（或提供级联删除选项）
- **FR-047**: 系统必须在角色权限详情中区分"继承权限"和"自有权限"

### Key Entities

- **权限 (Permission)**: 系统中可执行的操作或可访问的资源。包含权限代码（如 "user:create"）、权限名称、描述、父权限（支持层级结构）、创建时间。
- **角色 (Role)**: 权限的集合，由租户管理员创建和管理。包含角色名称、描述、状态（启用/禁用）、所属租户、关联的权限列表、父角色 ID（支持继承）。
- **权限模板 (PermissionTemplate)**: 预定义的权限组合，用于快速创建角色。包含模板名称、描述、权限列表、所属租户、是否系统预定义。
- **数据权限规则 (DataPermissionRule)**: 定义用户的数据访问范围。包含用户 ID、租户 ID、权限类型（全部/部门/个人/项目）、关联的部门/项目 ID、创建时间。
- **用户-角色关联 (UserRole)**: 用户和角色之间的多对多关系，记录用户被分配的角色及分配时间。
- **用户-权限关联 (UserPermission)**: 用户和权限之间的直接关联，记录用户被直接授予的额外权限。
- **会话 (Session)**: 用户的登录会话信息。包含会话 ID、用户 ID、租户 ID、登录时间、最后活跃时间、设备信息、IP 地址、状态（活跃/已下线）。
- **黑名单 (Blacklist)**: 被禁用的用户列表。包含用户 ID、租户 ID、加入时间、移除时间、加入原因、操作人、状态（生效中/已移除）。
- **权限验证日志 (PermissionLog)**: 记录所有权限验证操作。包含用户 ID、操作、资源、结果、时间、IP 地址。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 权限验证响应时间在 10ms 以内，不影响接口性能
- **SC-002**: 同一账号在多个设备登录时，旧设备在 2 秒内收到挤号通知
- **SC-003**: 管理员强制下线指令在 3 秒内生效，用户被踢出系统
- **SC-004**: 通过接口动态添加的权限在 5 秒内可用，无需重启服务
- **SC-005**: 黑名单用户加入后立即无法登录，现有会话在 2 秒内被终止
- **SC-006**: 黑名单用户被移除后，可在 5 秒内重新登录系统
- **SC-007**: 数据权限过滤准确率达到 100%，用户无法越权访问其他租户或部门的数据
- **SC-008**: 系统能够支持至少 10,000 个并发权限验证请求而不影响性能
- **SC-009**: 权限模块集成到其他项目的时间不超过 30 分钟（通过依赖引入）
- **SC-010**: 使用权限模板创建角色的时间比手动配置减少 80%
- **SC-011**: 数据权限过滤响应时间在 50ms 以内，不影响查询性能
- **SC-012**: 角色继承关系变更在 5 秒内同步到所有子角色
- **SC-013**: 系统能够检测并阻止循环继承，检测时间在 1 秒以内

## Assumptions

1. **权限模型**: 采用基于角色（RBAC）和基于属性的权限控制（ABPC）混合模型，支持接口权限和数据权限两个维度。
2. **权限注解**: 权限模块提供标准注解（如 @RequiresPermission），开发者只需在方法上添加注解即可声明所需权限。
3. **长连接方案**: 优先使用 WebSocket 作为长连接方案，如果不可用则降级为轮询或 Server-Sent Events (SSE)。
4. **Token 管理**: 假设使用 JWT Token 进行身份认证，Token 中包含用户 ID、租户 ID、权限列表等信息。
5. **会话存储**: 使用 Redis 存储会话信息，支持分布式环境下的会话共享。
6. **权限缓存**: 权限配置会被缓存以提升性能，权限变更时通过消息通知刷新缓存。
7. **黑名单范围**: 租户管理员只能管理本租户的子用户黑名单，不能影响其他租户。系统管理员可以跨租户管理所有用户的黑名单状态。
8. **动态权限安全性**: 权限配置接口需要系统管理员权限才能调用，普通租户管理员无法调用。
9. **黑名单状态**: 黑名单有两种状态——"生效中"和"已移除"。移除后的黑名单记录会被保留用于审计，但用户可以正常登录。
10. **权限模板**: 系统预定义的模板不可删除和编辑，租户只能创建自己的自定义模板。模板变更不影响已创建的角色。
11. **数据权限实现**: 数据权限通过 MyBatis-Plus 拦截器实现，自动在 SQL 查询中添加过滤条件（如 WHERE dept_id = ?）。
12. **角色继承限制**: 角色继承最多支持 5 级，防止继承链过长影响性能。循环继承检测在角色创建和编辑时执行。
13. **数据权限降级**: 当数据权限过滤字段在表中不存在时，系统跳过该过滤规则，不影响查询执行，并记录警告日志。
